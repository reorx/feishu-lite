# 邮箱阅读器收尾验收与全界面 UI 审查

## 背景

用户 2026-10-17 的要求：先把剩余功能做完并验收；然后由 Claude Code 做一次足够仔细的全界面 UI 审查（用户已注意到边框、边界等处观感不好），整理成 review 文档交用户审视。

### G2a：自动基线与系统/键盘边界

额外必读：[F2a 报告](../sessions/2026-10-14-email-system-notifications-f2a.md)「工具与未验边界」；[F2c 报告](../sessions/2026-10-14-email-keychain-chat-f2c.md)「首败、工具修正与自主决定」「遗留问题」；[F1b 报告](../sessions/2026-10-14-email-reader-f1b-acceptance.md)「与 F1 合并后的剩余项」里关于未知能力的一句。`tmp/2026-10-14-email-reader/` 下 F2a/F2b/F2c 的 fixture 和工具可以复用，复用前先审计它们对旧名称的假设（FeishuChat bundle id、旧模块和 target 名），改名后这些都变了。

范围：

1. **自动基线**：在当前 HEAD 跑 `cd backend && uv run pytest` 和 `cd mac && make test && make build`，记录各自数量（改名 session 记录的是后端 311、Core 74、App 98）。有失败先保留原始输出，判断是不是产品回归；是回归就停在这里交协调者，因为后面的验收建立在这个基线上。
2. **未知能力稳定加载 UI**：在隔离副本里只延迟能力输入，造出稳定的 unknown 窗口，截图确认这段时间的界面状态合理。
3. **R3 未知投递提示的键盘操作**：提示里的按钮能用 Tab 聚焦、用 Return 触发。
4. **邮箱故障期间聊天 Return 发送**：在 auth_failed 或受控超时期间，聊天输入框按 Return 发送。记录 native key event、焦点、markedText 和 POST 请求时间，证明事件到达与请求发生一一对应。F2c 的失败在于没拿到这种对应证据，不要再用按钮发送代替。
   中文 IME 组字：只有不改全局设置就能用输入法时才补，否则明确记为未验。不能用 AX 设值或 Unicode 注入冒充组字，因为那绕开了 markedText 路径，正是要验的东西。
5. **通知边界**：稳定账号运行中关闭、再恢复本测试 App 的通知权限（F2a 首轮失败是 fixture 恢复了已移除的旧 UUID，注意避开）；410 或旧账号的通知点击；升级前遗留的聊天通知 payload；系统 add 部分失败。最后一项只能注入时，可在隔离副本注入，并在报告里写明是注入。

不做：WebKit 竞态和安全（G2b）、真实邮箱（G1）、已通过的旧矩阵。

完成标准：上面每一项都有通过、失败或未验的结论和证据路径；失败项有最小复现，并判断是 UI 缺陷还是功能缺陷；自动基线的命令和数量写进总结。

### G2b：WebKit 竞态与安全边界

G2a 的接续信息（协调者补）：

- G2a 已在 `9119dfb` 签收，见 [G2a 总结](../sessions/2026-10-17-email-g2a.md)。它在 `tmp/2026-10-17-email-reader-finish/g2a/` 留下了改名后可用的源码副本、合成服务和观察器，可以复用；复用时去掉 G2a 的注入（能力延迟、add 错误注入、通知权限相关播种），重新建独立 HOME，改用自己的 bundle id 和端口。
- G2a 踩过的工具坑：观察器读键盘 `NSEvent.eventNumber` 会抛异常并中断分派，改读 timestamp；固定目录层级复用 fixture 时找不到文件；长文本键入中途会失去激活，用短文本并先确认焦点。
- 本机系统设置里“键盘导航”是关闭的，进程级参数无法打开它，不要依赖 Tab 聚焦按钮。
- G1 阶段一同时在跑，它只起后端、用 18911–18919，不占桌面；G2b 结束后 G1 才进入界面阶段，所以 G2b 做完要及时交付。

额外必读：F1b 报告全文（尤其“最小接续”）、[R1 报告](../sessions/2026-10-14-email-html-scroll-r1.md)、[D2 session](../sessions/2026-10-13-email-reader-d2.md) 的正文渲染与已读契约。

范围：

1. **旧回调乱序**：给隔离副本的 controller 观察记录补上每个 didFinish 候选和 navigation 身份（只加观察，不绕过策略），证明旧 HTML didFinish 不会触发 read；F1c 留下的纯文本精确旧 layout 回放同理。
2. **已发 STORE 期间身份变化**：可控服务暂停 read 响应，期间切换合成账号或 UIDVALIDITY 世代，确认迟到结果被隔离，界面和计数正确。
3. **用户点击外开**：用 loopback TLS 页面验证 HTTPS 链接外开；单标签内网主机（如 `http://intranet/`）的实际外开行为符合 C1 的决定（保留合法 HTTP(S) 内网链接）。
4. **跨邮件与 token 访问探测**：在正文里尝试读取其他邮件、本地接口 token 和聊天数据，确认全部拿不到。

不做：G2a 的项、真实邮箱。

完成标准：同 G2a。

### G1：真实邮箱接入与浏览

用户 2026-10-17 的决定见决定表：不发测试邮件，不验已读和跨端，只验登录我们提供的账号后能否正常打开、浏览邮件。额外必读：[A 探路笔记](../notes/2026-10-13-email-imap-probe.md)、[C3b session](../sessions/2026-10-13-email-api-c3b.md) 的 API 契约、[D1 session](../sessions/2026-10-13-email-configuration-d1.md) 的配置与钥匙串流程、`kb/docs/email-foundation.md`。

同一个 agent 分两段做。

**阶段一：无界面接入扫描**（现在开始，和 G2b 并行）

- 隔离：独立的 `FEISHU_LITE_HOME`，端口 18911–18919，用当前源码 `uv run --project backend feishu-lite-backend --port P` 起后端，只通过后端 API 配置账号。不碰正式数据目录，不碰正式 App 拉起的后端。凭证用 envops 从 `tmp/feishu-mail.env` 注入进程，值不出现在命令行参数、日志或文件里。
- 验证：
  1. 账号配置与试连。
  2. 全部文件夹的 LIST：中文名、层级、INBOX 识别；其他文件夹在后端也拒绝读取。
  3. 收件箱 100/50 分页翻到底；邮件太多时至少翻到覆盖一年以前的邮件，覆盖近期和较早邮件。
  4. 抽样取正文：最近一页全部，再每隔几页抽样，合计至少 150 封（全箱不足就全取）。统计 HTML、纯文本、空正文、占位、解析错误的数量，编码种类，附件元数据，单封耗时。
  5. 取正文前后整箱未读数不变，证明 GET 正文不写 `\Seen`。
  6. 首次同步不产生 pending 和通知；重启后端后不重复产生 pending。
- 只记聚合统计和脱敏结构，不记主题、发件人、地址、正文。解析或展示失败的邮件只记 UID、MIME 结构、错误类别；需要原文复现时，脱敏后放 tmp，交协调者。
- 阶段一做完：把结果写进总结（可以先不提交），在 tab 里回复“G1 阶段一完成”和一句话结论，然后停下，等协调者通知桌面空闲。

**阶段二：在 App 里浏览**（协调者通知 G2b 已释放桌面后再做）

- 编一个隔离 Debug 副本（独立 bundle id、HOME、数据和偏好），在配置页填入真实账号。密码用 envops 取得后输入，不出现在日志、截图和命令行参数里。钥匙串条目只能写在 Debug service 下的新 UUID，结束后精确删除并确认已不存在。
- 浏览：文件夹下拉、收件箱列表滚动与翻页、长主题和中文、HTML/纯文本/带附件的邮件各打开几封、附件信息，深浅色各截一张。只打开本来就已读的邮件，不改变未读状态，可以用阶段一的统计挑 UID。
- 截图里有真实邮件内容，只留在 tmp（已 gitignore，不入库）；报告里只描述现象，不引用内容。

不做：已读、跨端、新邮件通知的专门验证；发信；断网和睡眠；G2a/G2b 的项。

完成标准：两段的每一项都有通过、失败或未验的结论和证据路径；真实邮件里出现的解析或展示问题有分类统计和脱敏复现；用 grep 检查日志和证据目录，确认凭证零泄漏；测试钥匙串条目、进程、隔离目录都已清理。

### U1：全界面 UI 审查

剩余验收全部签收后派发。执行者是 Claude Code，只审查、截图、写文档，不改产品代码。

目标：一份足够仔细的 UI review，让用户能据此判断问题清单是否完整，再决定修哪些。

范围：Messages 和 Email 两个模块的所有界面状态。包括窄导航和 badge；会话列表（含管理多选、隐藏列表）；聊天详情（消息、图片、会议邀请、系统消息、输入框、草稿）；扫码登录页；邮箱配置页及各错误状态；收件箱列表；邮件详情（头部、HTML、纯文本、附件信息）；空态、加载、离线、失败提示；未知投递提示；设置和菜单；深浅色；最小窗口与拉宽。

重点看：

- 边框和分隔线：重复、缺失、粗细不一、没对齐，以及在窗口边缘、工具栏、分栏交界处的处理。用户特别指出了这一类。
- 间距与对齐、字号与层级、颜色对比。
- 控件样式是否符合 macOS 习惯；选中、悬停、焦点状态。
- 截断与换行、滚动边缘。
- 同类组件在两个模块间是否一致。

方法：

- 用隔离副本和合成数据，不碰真实数据。G2a/G2b 在 `tmp/2026-10-17-email-reader-finish/g2a/`、`g2b/` 留下了改名后可用的源码副本、合成聊天/邮件服务和启动脚本，可以复用；去掉其中的注入和观察插桩，改用自己的 bundle id 和端口。
- 合成数据要能把各种状态都造出来：长名字、长主题、多行消息、图片、会议邀请、系统消息、未读和 99+、空列表、错误和离线。
- 每个状态截深浅两色。边框和分隔线类问题用 Retina 原分辨率截图，再局部放大到像素级看。可以拿系统自带的“邮件”“信息”做 macOS 习惯的参照。
- G1 阶段二的截图（`tmp/2026-10-17-email-reader-finish/g1/`）是真实 HTML 邮件在 App 里的渲染效果，可以作为正文展示的参考。里面有真实邮件内容，review 文档里只描述现象，不引用内容，也不把这些截图复制到别处。
- 对照源码，把每个问题定位到视图文件和行。
- 本机系统设置里“键盘导航”是关闭的，不要依赖 Tab 聚焦按钮，也不要改这个全局设置。

产物：`kb/reviews/2026-10-17-ui-review.md`。每个问题写明：位置（界面和状态）、现象、截图路径、对应源码 `file:line`、严重度（影响使用 / 明显难看 / 细节）、修改方向建议（不写代码）。另附“已检查但没发现问题的界面”清单，让用户知道覆盖范围。截图放 `tmp/2026-10-17-email-reader-finish/u1/`。

## 共同约束

- 只做自己的任务，做完就停，不开始下一个任务，不改本文件。原因：协调者要按上一个任务的实际产出定下一个任务的 brief。
- 工作目录 `/Users/reorx/Code/feishu-lite`，分支 master。不建分支或 worktree，不 push、不发布、不打 tag。
- 只 `git add` 自己改的文件，并用 `git commit -m "..." -- <自己的文件>` 只提交这些路径。原因：G1 和 G2b 同时在这个 checkout 里工作，普通 `git commit` 会把对方暂存的文件一起提交。`kb/todo.md` 有用户未提交的改动，不要暂存或修改它。
- 归协调者的共享文件（known-issues、next-up、根和 mac 的 AGENTS.md、README、原计划勾选、本文）不要改，要改的内容写进总结的「交给协调者」。
- 不自己开辅助 tab，不委派其他 agent。context 超过 40% 时停在一个干净的点，在总结里写好接续，回复协调者，由协调者开新 tab。原因：用户要求实机验收用新的 context，协调者也要掌握所有在跑的 agent。
- 验收任务不改产品代码。发现缺陷就写最小复现交协调者；验收工具、fixture、观察用插桩只放在 tmp 下的副本里。原因：用户要求 UI 修改由 Claude Code、功能修改由 Codex 的返修任务完成，验收者顺手改产品会混淆谁修的、谁验的。
- 隔离：只运行自己编译的隔离副本，用独立 bundle id（如 `com.reorx.FeishuLite.g2a-acceptance`）、fake SecItem、独立 HOME/数据/偏好和合成服务。不读真实的 `~/Library/Application Support/FeishuChat/`，不碰正式 App 及其权限和偏好，不读写真实钥匙串条目，不用 `make run`。用户的正式 FeishuLite 可能正在运行，不要结束它。
- 端口：G2a 用 18881–18889，G2b 用 18891–18899，U1 用 18901–18909，G1 用 18911–18919，用之前确认空闲。
- `tmp/feishu-mail.env` 里是真实邮箱凭证，只有 G1 可以用，而且必须通过 envops 技能操作；不输出值，不写进日志、报告或 git。其他任务不读它。
- 聊天：只有群 litetest 获准发消息。本轮的隔离任务都用合成聊天服务，不连真实飞书。
- 会弹系统通知或扫码页的测试看起来和真的一样，协调者会提前告诉用户；执行者在总结里列出实际弹过哪些。
- 不跑 formatter 或 style linter。返修任务遵守根 AGENTS 的测试先行规则：修 bug 先写复现测试。
