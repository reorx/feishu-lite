# 邮件同步、缓存与安全正文

供接续邮箱开发和审阅的人阅读：邮件账号如何恢复、同步如何保持身份和提醒关联，以及哪些正文可以展示。后端已有独立同步服务与隔离验证的 IMAP 适配器，Email 工作区仍是占位；HTTP/SSE、进程生命周期和阅读界面尚未接入。

## 账号与独立同步

邮箱配置与聊天身份独立。地址第一次配置或更换时生成新的 UUID；更换地址和移除邮箱先撤销任务，删除旧邮箱缓存，并返回旧账号 id 供 App 清理钥匙串和通知。地址/账号保存在 mail.db，密码仅在内存 SecretStr 中；服务重建后等待密码注入，缓存和水位保持。相同密码的重复注入没有连接或水位副作用，已被拒绝的相同密码也不重试。

本机邮件服务分为未配置、缺凭证、连接中、在线、离线和认证失败。断网保留旧未读数和最后检查时间，并标记计数过期；认证失败等待凭证变更。网络重连采用最长 60 秒的退避。一个后台循环合并手动刷新、IDLE 信号和默认 45 秒整箱对账；无 IDLE 时也用这个周期检查新信。持续推送留出至少 100ms 合并窗口，避免忙等。强制重连的刷新会等待新连接对账后才返回成功。

第一次 SELECT 的 UIDNEXT 是历史/通知基线。历史导入静默，初始化间隙不小于基线的 UID 仍进入增量。初次导入被中断时沿用原基线补抓历史摘要，不把保存过 SELECT 信息当成导入完成。每轮按整箱 UNSEEN、新 UID 和缓存存在查询对账，过滤 n:* 返回的低水位尾 UID。存在查询及摘要 FETCH 每批最多 100 UID，不扫整箱 FLAGS。SELECT 观察到 UIDVALIDITY 改变时重建并发出目标失效信号。

## 邮件身份与独立缓存

邮件身份由邮箱账号、服务端文件夹标识、UIDVALIDITY、UID 四项组成。INBOX 按协议语义不区分大小写，适配器统一为 `INBOX` 键，名称仍保留 LIST 原值；其他文件夹保留原标识。Message-ID 和 IMAP 序号都不能代替它。对外标识和分页游标分别带类型及版本，并编码成不含斜杠的 base64url；游标只能在原账号、文件夹和 UIDVALIDITY 中使用。

缓存位于独立的 mail.db，和聊天 cache.db 分开。账号移除不会清聊天；文件夹 UIDVALIDITY 改变会一并失效旧摘要、正文、未读快照和待提醒目标。重复连接同一世代只刷新文件夹信息，保留缓存和水位。文件夹目录可以保存整个 LIST 结果，未支持的文件夹不需要被 SELECT 才能列出。

列表读取摘要，不依赖正文。摘要按 UID 倒序排列，首次最多 100 封，后续默认 50 封；UID 可以不连续，收件时间不参与分页排序。在线服务按服务端 UID 列表切片填充较早页；离线只返回当前缓存页，不能把缓存末尾解释为服务端已经没有历史邮件。

整个收件箱的未读集合独立于摘要缓存，未读数不受当前页大小影响。摘要里的 flags 会在整箱对账时同步更新，其他标志得以保留。

## 可恢复的提醒

新增提醒摘要、同步水位和待提醒批次在同一事务写入。只有新 UID 在服务端最终未读快照中仍未读才提醒；历史回填、旧邮件改未读和世代重建静默。单次超过 3 封或有已知收件时间比发现早 10 分钟以上时汇总，其余逐封。批次模式在创建时固定，部分目标被读/删后不改变；未知收件时间的错误占位不用于推断邮件年龄。

领域事件发出不等于提醒已处理。App 处理整批（包括逐封投递或抑制）后确认批次，后端才推进通知水位；乱序确认不会越过尚未确认的较早批次，重启会继续保留待处理批次。单封系统通知使用稳定邮件键，汇总使用稳定批次键；重复状态/事件只覆盖同一目标。已经确认的旧 UID 不会被后来一批重新加入。邮件删除或变为已读会清理其待提醒关联；空批次允许推进水位，不要求提醒一个已经不存在的目标。具体 SSE 接线与 App 投递仍未实现。

## 正文与附件

先从 BODYSTRUCTURE 选择正文，再获取那个 section 的 BODY.PEEK literal。alternative 优先 HTML，related 使用 start 指定的根或第一个部分；attachment 和 message/rfc822 子树不能成为正文。附件只保存文件名、媒体类型、content-id 与可得的编码后大小；大小标注为近似，multipart 附件大小未知。领域基础没有附件下载接口。

头部及附件名支持 RFC2047/2231。未声明编码依次尝试 UTF-8、GB18030；gb2312/gbk 声明统一按 GB18030 解码。未知 charset、畸形 transfer encoding 或超限都返回安全错误代码，不把服务端文本带入错误信息。

正文缓存保存解码后的原始文本，每次阅读再按当前政策净化。HTML 保留文本、基本排版与表格，移除脚本、表单、frame、自动跳转、所有样式及资源属性。图片变成文字占位。链接仅允许具有有效 host 的显式 HTTP(S) URL；合法 IP、单标签内网名和内网域名都可以由用户主动点击外开。相对链接、其他 scheme 和畸形 URL 移除。href 本身不授权自动网络加载；点击外开、全网络阻断与明确用户手势边界由 App 实现。

后端净化不代表 WebKit 已安全验收。D2 还需要非持久化 WebKit、JavaScript 禁用、CSP、第一封邮件加载前挂载网络规则，以及所有导航/新窗口处理。

## 邮箱通信与停止

适配器列出全部文件夹，但内容操作只允许 INBOX。连接默认验证 TLS 证书与主机名；认证失败使用邮件领域错误，与聊天登录无关。正文 PEEK 没有已读副作用，显式已读只添加 Seen，并检查目标仍存在且服务端返回该标志；真实跨端和重连持久化仍需后续验收。

每条连接由一个专用 daemon 线程持有，命令串行执行。正文、缓存净化和已读优先于排队的后台请求；IDLE 有请求时先 DONE，等待确认后才发下一命令。推送只触发需对账信号，周期及重连策略由同步服务负责。网络 literal、响应大小和结构复杂度在库分配/解析前受限；无法安全继续读取时连接退役，避免把后续响应错配到别的邮件。

停止先撤销所有待交付结果，再通过 socket shutdown 打断阻塞 I/O，由所有者关闭资源。服务在每个异步结果后核对账号、生命周期、连接 identity 和 UIDVALIDITY。所有者停止在取消前就登记并受到保护，网络和离线净化所有者同时停止。平台 DNS 解析尚无 socket 时无法强制结束线程：停止在 1.5 秒期限返回明确超时，daemon 不拖住进程，DNS 恢复后禁止再建连；服务保留退役记录，等待 closed 后才能创建新网络实例。真实断网/睡眠仍待整体验收。

摘要库解析或网络结构超限导致连接退役时，服务缩小批次隔离单封；每轮最多 8 次隔离重连，之后保存可重试占位，给正常对账留下完整连接。未读新信的占位也保留提醒目标；已确认单封错误不在周期里反复 FETCH，隔离预算内未尝试的摘要可在用户加载该页时重试。缓存正文由独立、不联网的所有者重新净化，因此网络连接失效不影响缓存阅读。显式已读串行验证 STORE 和整箱 UNSEEN；读取正文从不提交 Seen，离线没有待写队列。

## 开发入口

- `backend/src/feishu_lite/mail/types.py`：共享模型、标识、限额。
- `backend/src/feishu_lite/mail/store.py`：schema 与原子缓存操作；SQLite 只由事件循环所属线程使用。
- `backend/src/feishu_lite/mail/mime.py`、`html.py`：不含网络和 SQLite 的解析、正文选择与净化，可交工作线程执行。
- `backend/src/feishu_lite/mail/imap.py`、`executor.py`、`transport.py`：INBOX 异步接口、串行所有权、可中断 IDLE 与读取边界。
- `backend/src/feishu_lite/mail/service.py`：独立账号、同步、分页、提醒及缓存阅读服务；不依赖聊天登录。
- `backend/tests/mail/`：全部合成的身份、存储、编码、HTML 及失败隔离行为测试。
