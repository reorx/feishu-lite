## 新发现 / 未修全：V1a-01

**展开抄送后仍省略地址（明显难看，关联 U1-13，建议 Claude Code 修界面）。**

- 位置：Email → fixture UID 300 富 HTML 邮件 → “展开抄送”。
- 最小复现：选 UID 300，点“展开抄送”，把窗口放宽至 1720×1060。6 个地址低于滚动阈值 8，按钮已变为“收起”，地址仍被截成一行，末尾“抄送人4 <cc4…”，其余两人不可见，也没有滚动入口。1100×720 同时展开收件人/抄送也复现。
- 窗口矩阵（深浅色一致）：800×512 只展开抄送或同时展开两项均完整；1720×1060 两种展开方式均截断；1100×720 同时展开两项截断。因此不能写成所有窗口都失败。
- 证据：`e02b-header-expanded-{light,dark}.png`、`zoom/e02b-cc-expanded.png`、`v1a-{min,wide}-cc-expanded-*`、`v1a-{min,wide,normal}-all-addresses-expanded-*`；fixture 地址完整，并非输入本身省略。
- `mac/FeishuLite/UI/MailMessageDetail.swift:111` 的展开分支；`126` 行为未超过阈值时的 Text，`123` 行只给超过阈值者滚动高度。这里定位展示分支，不声称已定位 SwiftUI 内部布局根因。
- 建议：让少于阈值的展开地址在正常/宽窗口也获得完整换行高度；超过阈值时滚动。保留最小窗口正文空间，不用会把分栏撑高的 `fixedSize(vertical:)` 规避；修后同时检查静态尺寸与窄→宽调整。

没有发现其他需要单独列项的新问题。U1-11/U1-19 的排除项按用户决定处理；R8 已接受的慢速翻页等待未作为新缺陷重复报告。
