# R8：邮件阅读器返修

## 概要

按 [UI 返修协调 brief](../plans/2026-10-18-ui-fixes-coordination.md) 的 R8 一节完成邮件阅读器的界面返修，起点 `5c54618`（R7 签收于 `e803fb9`）。HTML 外壳 CSS 不再给所有表格画框，深色下正文和头部同一底色；邮件头部按内容定高，收件人和抄送折叠成一行；正文的字号、行高、左边距和最大阅读宽度在 HTML 和纯文本之间统一；附件区、文件夹菜单、列表的错误与空态、配置表单、日期格式和正文永久错误也一并改了。

只改了邮件阅读器相关的视图、两个正文控制器的外观，以及 Core 里的外壳 CSS 和几项展示逻辑（新文件 `MailPresentation.swift`）。CSP、nonce、禁 JS、block-all 规则、WK 导航和 delegate、后端白名单都没动。后端 312、Core 97（基线 88，新增 9）、App 112 全部通过，`make build` Debug 成功。

### 逐条说明

- **U1-11**：外壳 CSS 去掉了 `td, th { border }`。单元格只留很小的内边距和顶端对齐；只有自己的行里有 `th` 的表格（`table:has(> thead > tr > th, > tbody > tr > th, > tfoot > tr > th)`）给本表的单元格画 1px 框、表头加浅底。用直接子选择器，是为了让嵌在布局表格里的数据表格只给自己画框，外层布局表格不受影响。没有表头的数据表格不画框，只靠对齐和间距，这是取舍。另外统一了引用块、代码和分隔线的样式，都在外壳 CSS 里。
- **U1-12**：WKWebView 不画背景，`html, body` 透明，正文透出窗口底色。KVC 的 `drawsBackground` 在 macOS 26 上落到 `_setDrawsBackground:`（没有不带下划线的 setter，见首败第 9 条），所以先判断两种 selector 有没有，都没有时保持默认、不崩溃。`underPageBackgroundColor` 设为透明。没动导航、内容规则和 delegate。
- **U1-13**：头部去掉了 `ScrollView` 和 `maxHeight: 160`，按内容定高。标签列按“收件人”定宽，发件人行右侧是日期。收件人和抄送默认一行：一个人时显示“名字 <地址>”，多人时列前两个名字加“等 N 人”，带“展开”。展开后最多 8 人时整段显示；超过 8 人放进 72pt 高的滚动区，下面一行“共 N 人，滚动查看全部”。头部和附件区用 `layoutPriority(1)` 先取高度，剩下的给正文。没用 `fixedSize`，因为分栏会按很窄的宽度询问最小高度（mac/AGENTS.md）。
- **U1-19**：列表用 `ChatTimeFormat.listLabel`，和会话列表一致，往年显示 2025/12/30；头部用 `messageLabel`。两处都从 `\.today` 取“现在”。
- **U1-20 / U1-35 / U1-41**：排版常量放在 Core 的 `MailReaderLayout` 里：左右边距 20、上下边距 20、正文 14pt、行高 1.5、最大阅读宽度 720、主题 17pt、h1–h3 为 16/15/14px。HTML 外壳 CSS、纯文本控制器和头部都读这些常量。纯文本用 `lineSpacing` 补到 1.5 倍行高。文字列宽是 `min(宽度 - 40, 720)`，靠左。纯文本的位置恢复仍以上边距 20 换算，所以 R2 的恢复测试不用改。
- **U1-21**：Core 的 `MailFolderMenu` 按 delimiter 找最近的、也在列表里的上级，子文件夹排在父文件夹后面，收件箱排第一。菜单项只显示名字，用全角空格缩进；当前文件夹用 Toggle 打勾；不能读取的禁用（灰显）；有不能读取的文件夹时，底部加一行“暂只支持读取收件箱”。按钮文字是当前文件夹的名字。
- **U1-22**：`sidebarStatus(now:)` 在配置表单显示时不再带 `errorMessage`，所以同一条错误只出现在一处：表单开着时在表单里，在阅读器里时在侧栏状态里。我没有把它完全移出侧栏，因为同步和恢复出错时用户看不到表单。列表为空时，错误只在列表中央的空态里显示，附“重试”；有缓存时才放在底部的提示条里。刷新进行中，底部的旧错误换成“正在刷新收件箱…”。空态的说法按状态选：刷新中、未配置、有错误、等待首次同步、没有邮件。
- **U1-31**：新增 `ListEmptyState`（在 `ShellComponents.swift`），是列表里的小空态：小图标、次要色文字、可选的说明和按钮。主要区域用 ContentUnavailableView：“选择一封邮件”、“正文未能显示”，以及叠在正文上的“正文为空”。正文为空时 `MailPlainController` 不再写“（正文为空）”，正文视图照常完成布局、给出显示证明，空态只是叠在上面，不响应点击。所以可见性已读的证明链不变（`r8/gui-checks.json` 的 `empty_body_displayed: true`）。
- **U1-36**：附件区不再用 DisclosureGroup。标题“附件 N 个 · 仅显示信息”下，每个附件一行：类型图标、文件名（中间截断，悬停显示全名）、类型名和大小。类型名由 Core 的 `MailAttachment.typeDescription` 给出，先认扩展名，再认 MIME，比如“Excel 表格”“ZIP 压缩包”“TAR.GZ 压缩包”。不足 1000 字节显示“312 字节”，避免英文 “bytes”。最多 3 个时全部列出；更多时列 3 个加“还有 N 个”，展开后最多 6 个时全部列出，超过 6 个放进 118pt 高的滚动区，并提示“共 N 个，滚动查看全部”。
- **U1-37**：“已读同步未完成”改用 `NoticeBar(.warning)`：标题“已读同步未完成”，原因作说明，按钮“重试已读同步”，禁用条件没变，放在头部和正文之间，下面接 Divider。`routeError`（“这封邮件已不存在或已失效…”）也改用同一个提示条。“加载更早的邮件”改成居中的无边框按钮，加载中换成一行进度；列表为空时不显示这一行（见首败第 8 条）。
- **U1-38**：邮箱地址和专用密码有占位文字（“name@company.com”“飞书生成的专用密码”）。“移除邮箱”的文字是红色，禁用时灰色。“返回阅读器”移到工具栏的导航位置，是一个返回箭头，原来那一行和分隔线去掉了。表单里的错误加了图标。
- **U1-39**：正文失败时用 `mail.canRetryBody` 决定是否显示“重试正文”。

## 设计决定

- **最大阅读宽度 720pt，没有照审查的“70–80 个汉字”**：14pt 下 70–80 个汉字是 980–1120pt，在 1720pt 宽的窗口里仍然占掉大半个详情区。720pt 约 51 个汉字或 100 个英文字符，HTML 营销邮件常见的 600px 布局也放得下。内容靠左，和头部同一左边距；居中会让左边距随窗口宽度变化，和头部对不齐。
- **头部和附件的“上限”按人数或个数定，不按测得的高度定**：试过 `ViewThatFits`，在 Grid 里拿不到确定的尺寸，选中滚动版后只剩一行高；放进 HStack 后，和会抢高度的正文并列时，要么多出空白，要么被压扁（首败第 4 条）。按个数定上限更确定，代价是窄窗口里 8 个收件人可能折成 5 行左右。
- **错误按“表单是否在显示”分配位置**，没有按错误种类分，理由见 U1-22。
- **头部日期用 `messageLabel`**：今天只显示时分，和聊天里消息的时间一致。
- **“返回阅读器”只用图标加悬停说明**：工具栏导航位置的返回箭头是系统常见做法，标题“邮箱配置”就在旁边。

## 布局测试的修改

- `MailNoticeLayoutTests.unknownDeliveryNoticeTakesDetailSpaceWithoutPushingSplit`：原测试把“详情栏最上面的 AppKit 滚动视图”当作头部，并断言没有提示条时它在 20pt 以内。U1-13 之后头部是普通 SwiftUI 文字，没有自己的滚动视图，正文状态下量到的是头部下方的正文。改为分别取两个基准：正文状态下头部高度在 120pt 以内（实测 89pt，也钉住了“头部不再固定 160pt”）；配置状态下表单从详情顶部开始（< 20pt）。有提示条时，各状态和各自的基准比，至少低 40pt。其余断言不变：分栏等于宿主、侧栏列表不动、剩余高度 ≥ 200、放大字号后更低、不额外请求、不 read/ack/投递。
- `inboxWithoutNoticeKeepsItsFullHeightAcrossReconstruction`：同样的原因，初始位置的断言从 `< 20` 改成 `< 120`，重建前后位置相同的断言不变。
- `MailPlainScrollTests.plainEmptyAndLongDocumentLayoutAndRestoreAreBounded`：空正文的文字从“（正文为空）”改成空串，并加了一条断言：空正文仍然给出显示证明（`mail.displayedToken == empty.token`）。

新增测试：Core `MailPresentationTests`（8 个，文件夹层级与顺序、孤儿文件夹、可读判断、按钮文字、附件类型名两组、收件人折叠两组），`MailHTMLTests.envelopeFramesOnlyDataTablesAndMatchesTheNativeReaderTypography`（1 个）。先写测试，在没有实现时编译失败（`r8/core-red.log`），实现后通过（`r8/core-green-1.log`）。钉住 CSP 的 `documentHasStrictCSPNoBaseAndBlocksEveryResource` 没改，原样通过。

ListEmptyState(systemImage: "tray", title: "收件箱没有邮件")

               action: InlineAction(title: "重试", isEnabled: ready) { retry() })   // message: 可选的说明

居中、次要色，宽度撑满。主要区域（详情区）的空态继续用 ContentUnavailableView。注意：ContentUnavailableView 放在 VStack 里时要加 `.frame(maxWidth: .infinity, maxHeight: .infinity)`，否则不会撑满，同一列里的其他内容会被一起居中（首败第 10 条）。
