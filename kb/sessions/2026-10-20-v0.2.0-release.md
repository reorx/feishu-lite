# 发布 FeishuLite v0.2.0

## 概要

用户要求发布下一个 minor，以上一正式版 v0.1.2 为基础确定 v0.2.0。主要功能变化是侧栏工具栏模块图标、标题模块菜单和独立邮件文件夹菜单，来自已验收提交 `5502357`。

发布检查发现旧流程只给 DMG 钉公证票据，没有给 App 钉票据。本次先补五项行为测试，再引入 App zip 公证 → App staple → DMG 打包签名公证的共用脚本；DMG 终验必须验证内部 App 票据，stapler 网络错误退避重试。版本仍由 tag 决定，手动 CI 试运行使用 0.0.0。

- 正式 tag 固定到 `20a53c10bc3ca946674f14281c8d9891d96fe7ed`，同一提交也是 Cask 的后端固定版本。
- [Release](https://github.com/reorx/feishu-lite/releases/tag/v0.2.0)：DMG、SHA256SUMS、更新摘要及对应后端安装命令已发布。
- [试运行](https://github.com/reorx/feishu-lite/actions/runs/39438187416)、[常规 CI](https://github.com/reorx/feishu-lite/actions/runs/39438187559)、[正式发布](https://github.com/reorx/feishu-lite/actions/runs/39439084976) 全部成功。
- tap 的 `github-actions[bot]` 提交 `d3c72b2` 已更新 Cask 至 0.2.0。
- DMG SHA256：`43181cd412c6a814d0e587b28b81e7efb50a8c29cf28ff12587ad1ddc7b08d64`。

## 验证

- `make -C mac test`：Core 103 项、App 125 项通过。
- `cd backend && uv run --locked pytest`：312 项通过。
- 发布脚本测试：先执行新增测试并失败，再实现；最终 9 项全部通过，覆盖 Apple 拒绝、stapler 短暂失败、缺失内部 App 票据与挂载清理。
- `actionlint`、shell 语法和 `git diff --check` 通过；`make -C mac build` Debug 成功。
- 本地 `make -C mac release-local` 成功：App 公证 `773bef9b-998c-4149-996c-9b911b143d3e` 与 DMG 公证 `57c0675c-bf5d-43b5-83c5-bf4ba9dca1f2` 均 Accepted。
- 本地 DMG 挂载后检查：版本 0.2.0、固定后端 revision、x86_64 + arm64、深度严格签名、App / DMG 票据与 Gatekeeper 通过，`syspolicy_check distribution` 显示 passed all pre-distribution checks。
- 正式 CI App 公证 `05e47ea3-ea5d-44ac-bb27-ca55c1abbcab` 与 DMG 公证 `86893647-4fa3-4bb8-a4b1-5cddcdbfe8fe` 均 Accepted，内部 App 票据与 Gatekeeper 通过，Release / Homebrew 两个 job 均成功。
- 下载正式 DMG 后，SHA256SUMS、版本、后端 revision、双架构与签名检查通过；挂载内部 App 和复制到临时目录后的 App 均通过票据、Gatekeeper 及 `syspolicy_check distribution`。临时 App 和挂载均已清理。
- `brew update` 与 `brew fetch --cask reorx/tap/feishu-lite` 成功；tap Cask 与本地按正式版本、SHA256 和 commit 生成的文件逐字一致。发布说明与本地准备的更新说明一致。

## 修改的文件

- `mac/scripts/notarize.sh`、`mac/Makefile`：本地和 CI 共用两轮公证，新增 `notarize-app`、`notarize`、`release-local`。
- `.github/workflows/release.yml`：先公证 App 再打包 DMG，发布前检查内部 App 的票据。
- `mac/Config/Release.xcconfig`：默认安全时间戳，修正签名 Team 来源说明。
- `scripts/tests/test_notarize.py`：公证边界与失败行为的隔离测试。
- `AGENTS.md`、`mac/AGENTS.md`、`kb/docs/releases.md`、`README.md`：同步发布入口、两轮公证约定与实际发布结果。
- `kb/next-up.md`：保留干净用户验收项，更新为本版本及记录入口。
