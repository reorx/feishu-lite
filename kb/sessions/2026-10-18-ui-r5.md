# R5：复现会话卡死，修复尚未完成

## 结果

**U1-01：未修好，R5 未达到完成标准，不能签收。** 已稳定捕获与 U1 一致的 100% CPU 卡死，但所有尝试的修复仍在压力测试中失败。按 brief 的上下文 40% 停止约束，停在干净的接续点；未验证的产品代码全部撤回，本提交仅保存调查报告。没有开始 R6，没有 push、发布或打 tag。

证据统一在 `tmp/2026-10-18-ui-fixes/r5/`。只使用隔离副本、合成服务、假 SecItem、静默通知，未连接真实飞书/邮箱，未访问真实数据或钥匙串。

## 已确认与尚未确认的根因

U1 两份采样的主线程持续处于 SwiftUI transaction/AttributeGraph 更新，包含 `SelectionOverlay.updateNSView`、`FallbackAlignmentProvider`、NSTextField intrinsic-size 失效，以及逐行 `trackScrollRow → GeometryProxy.frame`。

旧源码确实存在无条件回写：会话详情的 preference 回调赋值 `isAtBottom` 与 `MessagesState.detailScrollAnchors`，另外两个使用方保存 `MessagesState.listScrollAnchors` 和 `MailState.listScrollAnchor`。无语义变化的几何更新仍产生回调；次数测试确定性复现了这一点。

但这些不是已确认的唯一根因：集中解析 anchor 并按语义去重后仍卡死；完全改用 AppKit 几何观察后仍卡死；替换可选择文本、移除 defaultScrollAnchor 的实验也没有消除卡死。最后在隔离副本中将 `onVisibleScrollRows` 的动作直接置空（禁用该入口的恢复、保存位置和底部状态赋值），仍然卡死；其他 onChange 入口没有同时禁用。**因此不能把“这个 preference 回调写状态导致死循环”写成已证实结论，尚需找出反复使图失效的真正来源。** 原始采样里滚动几何栈的出现可能是整个图反复更新的结果。

最终旧版对照 `baseline-native-stress.json`，总耗时 **226.435 秒**：

|---|---:|---:|---|
| 长会话滚动、最小窗口、邮件详情/配置、切回聊天 | 50 | 130.148 | 通过，结束 CPU 1.6% |
| 最小窗口、图片预览开关、宽窗口、深浅色与重选 | 1 | 7.245 | 下一轮滚动时卡死 |
| 窗口最小/宽幅往返 | 50 | 13.371 | 通过，1.5% |
| 深浅色往返 | 50 | 21.664 | 通过，1.5% |
| 模块往返 | 50 | 27.579 | 通过，1.3% |

`watch-68836.json` 记录 CPU **100.0%**；`watch-68836-sample.txt` 是独立 watchdog 保存的 3 秒采样，主线程样本集中于图更新，含 `trackScrollRow → GeometryProxy.frame`、SelectionOverlay/FallbackAlignmentProvider，与 U1 同源。全程最大心跳停更 **11.970 秒**，驱动随后退出该隔离进程。失败类别不能记为完成 50 轮。

驱动 `tools/stress.py`：Probe 主 actor 每 120ms 写状态，独立线程每 100ms 采样文件年龄；命令消费限时 4 秒，每轮检查心跳，每类结束保存 CPU sample 和 ps。图片预览要求打开、关闭均成功。最终滚动由隔离 Probe 操作目标 NSScrollView，避免全局滚轮事件受焦点影响；窗口和图片按钮仍用 AX，只匹配 `com.reorx.FeishuLite.r5-ui`。路径 2 每轮先回到底部，防止上一轮位置使脚本滚过图片。

## 尝试与首败记录

所有下列实验均已撤回，**都不能作为修好交付**。

- `test-red.log`：夹具的行没有撑满宽度，宿主改变宽度没有改变上报 frame，意外通过，不算红灯。补上撑满宽度后，`test-red-2.log` 在 50 次宽度/外观变化中回调 50 次，违反最多一次的断言。
- 第一版：逐行 bounds anchor、viewport 集中解析、语义快照、异步去重回调，并在首次布局后恢复位置。`test-green.log` 和后续 5 项行为测试通过；实际压力 `fixed-native-stress.json` 仍在图片路径卡死，`watch-94899.json` 为 100% CPU，采样仍有 SelectionOverlay 与集中解析的几何栈。第一条路径完成 50 轮不能掩盖此失败。
- 原生滚动观察：行 NSView marker、每 viewport 一个 NSClipView 观察器，完全取消 SwiftUI 几何 preference。`test-native.log` 的 5 项测试通过，但 `fixed-observer-stress.json` 仍失败，`watch-7908.json` 记录约 100% CPU。
- 可选择文本固定自然高度：`fixed-text-smoke-stress.json`，完成 1 轮后失败，`watch-15010.json` 约 99% CPU。
- 用原生可选择 NSTextField 代替 SwiftUI selectable Text：`native-text-smoke-stress.json` 仍失败；`watch-20634-sample.txt` 中更新热点变成原生文本 representable，不能仅凭原先 SelectionOverlay 很热就认定它是唯一根因。
- 去掉 defaultScrollAnchor：`no-default-anchor-smoke-stress.json` 仍失败。
- 原生观察 + 原生文本 + 去掉默认底部锚点：`combined-smoke-stress.json` 仍失败。
- 位置回调置空：`no-callback-build-2.log` 构建成功，`no-callback-valid-stress.json` 仍在会话重选命令时超时，最大心跳停更 3.950 秒。这个实验最值得接着分析。

另外保留的工具失败：

- `baseline-attempt1-*`、`baseline-stress.*`：AX 暂时没有窗口/图片按钮，未完成的轮次不计通过。
- `preview-probe.log`：心跳停更 47.8 秒，但当时没及时采 CPU 栈，不能单独认定与 U1 同源。
- `after-baseline-first-failure.log`：接续脚本原先要求旧版全部通过，遇到已取证的卡死后抛 AssertionError；修改为接受明确失败对照后继续。
- `test-behavior.log`：SPM 漏编译 today 环境值所在的 MainView，编译失败；补齐生产源文件后继续。
- `test-behavior-2.log` 到 `-5.log`：无窗口宿主的 scrollTo 恢复断言失败；最终挂到未显示的 NSWindow 后通过（`-6.log`、`-7.log`），未在屏幕显示测试窗口。
- `no-callback-build.log`：单独的 return 被 Swift 当成后面的 if 表达式返回，构建失败；该轮脚本误启动了旧二进制，`no-callback-smoke` 无效，不作为实验结论。修正为 return () 后重新构建并运行的 `no-callback-valid` 才有效。
- `watch-81408`、`watch-7012`、`watch-13896`、`watch-20060` 等 CPU 很低、RSS 约 15MB 的记录是启动时旧状态文件尚未替换的误报，不是已确认卡死；判断时检查对应 JSON 的 CPU 与采样。
