## 设计决定

### U1-10 选了“每个模块的侧栏顶部放切换控件”，没有用三栏

- 只有两个模块，三栏会让一整栏只放两行，最小窗口 800pt 下列表和详情都要变窄。
- 扫码页和邮箱能力页没有列表。三栏要给这些页面凑一个空的中间栏；两栏只需要在侧栏放头部和一句说明，详情放原来的页面。
- 保留“工作区按模块重建”：`RootView` 仍按模块用条件分支建 `MainView` 或 `EmailWorkspace`，每个工作区自带一个 `NavigationSplitView`，旧工作区（包括聊天输入框的 NSTextView）在切换时整个销毁。外层改用常驻的 `ZStack`，所以 `reevaluateViewing()` 的 onAppear 仍只在内容出现时触发一次，不会每次切换模块都多调一次。
- 侧栏的展开/收起状态放在 `RootView` 的 `@State`，两个工作区共用。侧栏宽度不能绑定，切换模块后回到默认宽度，这和修改前一样（以前每个模块也各有一个分栏）。
- 切换控件做成两段等宽、图标在上文字在下，没有用横排：最窄侧栏 240pt 时，横排的“图标 + Messages + 99+ badge”放不下。

### 其他决定

- 侧栏状态的语气：绿色正常；灰色是未配置、检测中这类中性状态；橙色是连接中、离线、未登录、后端不支持邮箱，以及密码只在内存里；红色是密码失效、等待密码和钥匙串错误。Messages 沿用原来“正常绿、其余橙”的规则。
- 邮件状态：一句话用 `stateDescription`。次要信息是“地址 · 同步于 时间”，有缓存未读数时再加“显示上次同步的缓存”。同步时间改用 Core 已有的 `ChatTimeFormat.messageLabel`（今天只显示时分，跨天显示“昨天”或“10月17日”），不再显示 “Oct 17, 2026 at 22:08”。收件箱列表和邮件详情里的日期仍归 R8（U1-19）。
- “检查邮箱配置”按钮缩短为“检查配置”，显示条件不变。密码只留在内存时，状态句末加“，密码尚未安全保存”，因为只靠橙点看不出原因。
- `mail.errorMessage` 仍显示在侧栏状态里（红字，最多 4 行），没有删。U1-22 要求每种错误只在一个位置显示，由 R8 决定保留哪一处（见交给协调者）。
- 提示条和状态行都不用 `fixedSize(horizontal: false, vertical: true)`，见“首败”第 2、3 条。同样的原因，`BackendCommandView` 的命令文字和聊天管理页脚的说明文字也去掉了 fixedSize。

## 布局测试的修改

- `MailNoticeLayoutTests.unknownDeliveryNoticeDoesNotOverlapInboxToolbar` 改写为 `unknownDeliveryNoticeTakesDetailSpaceWithoutPushingSplit`。原测试断言提示条把分栏整体往下推（分栏 minY ≥ 48，收件箱菜单在分栏下面）。U1-17 要求的正是不再这样做，所以改成断言：分栏始终等于宿主大小；侧栏收件箱列表的位置和没有提示时一样；详情栏最上面的 AppKit 内容（邮件头部、正文或配置表单的滚动视图）比没有提示时至少低 40pt，剩余高度至少 200pt；放大字号后提示条变高。仍然覆盖 1 条和 2048 条、收件箱/正文/配置/重建/放大字号 5 种状态，并保留不额外请求正文和列表、不 read/ack/投递的断言。尺寸改为 800×460 和 980×628，因为不再扣除 76pt 导航列。浮动侧栏盖在详情栏上，详情内容可以从 x=0 开始，所以按 NSSplitView 的两个子视图区分侧栏和详情，不按坐标。
- `inboxWithoutNoticeKeepsItsFullHeightAcrossReconstruction` 原来测收件箱菜单（NSPopUpButton）的位置。“收件箱”改成了 plain 样式的菜单（为了和“会话”同一字号），它不再是 NSPopUpButton，所以改测侧栏列表和详情内容的位置在重建前后一致。
- `ScrollAnchorTests` 两个列表测试只是补上新的 `status` 参数。
- 新增 `ShellLayoutTests`（2 个测试、5 种参数）：在 800×460 下，Email 的检测中、需要更新后端、未配置三页，以及 Messages 的在线和未登录两页，分栏都等于窗口大小。把 `BackendCommandView` 的 fixedSize 临时加回去时，“需要更新后端”这一例失败（`r7/shell-test-red.log`），去掉后通过。
- `mac/Package.swift` 的测试 target 加入 `UI/ShellComponents.swift` 和 `UI/LoginView.swift`（`MainView` 现在直接包含扫码页）。

## 首败和工具错误

1. 第一次截 e36 时没有提示条：Probe 播种的批次 id 和合成服务的待提醒批次不一致，收据被清理（`r7/capture-try1.log`）。改 Probe 后正常。
2. 第一次把提示条放进详情栏后，最小窗口下分栏被撑到 556pt 高，超出宿主（`r7/notice-test-1.log`）。原因是提示条文字用了 `fixedSize(vertical:)`：分栏会用很窄的宽度询问每一栏的最小高度，固定高度的文字会按逐字换行算出很高的最小值。去掉 fixedSize 后正常（`notice-test-2.log`）。
3. “请更新邮箱后端”页的侧栏整个空白（`r7/capture-full-1.log` 那一轮的 e34）：同样的原因，`BackendCommandView` 的命令文字把分栏最小高度撑到约 1790pt，内容被推出窗口上方（AX 树里分栏 y=-479、h=1790）。去掉 fixedSize 并补了 `ShellLayoutTests`。
4. 第一版的“全量截图”里，同步时间所在的次要信息行用了中间截断，地址过长时把同步时间截掉了，改为最多两行。
5. 布局测试第一版按 x 坐标区分侧栏和详情，配置页的滚动视图从 x=0 开始，被当成侧栏列表（`notice-test-3.log` 之前的那次）。改为按分栏子视图区分。
6. 放大字号的断言第一次失败：提示条标题写死了 `.callout`，环境字体不生效。改为标题跟随环境字体，通知权限提示在调用处设 `.font(.caption)`。
7. 合成服务日志里 ack 请求异常多，见交给协调者第 4 条。

## 接口说明

两个组件都在 `mac/FeishuLite/UI/ShellComponents.swift`。

### 提示条 `NoticeBar`

```swift
NoticeBar(tone: .warning,               // .warning（橙）或 .error（红），决定图标颜色和浅色底
          systemImage: "bell.badge",
          title: "有 3 条邮件提醒的投递结果未确认", // 跟随环境字体，可在调用处 .font(...) 调整
          message: "已保留待提醒邮件。",         // 可选，caption 灰字
          action: InlineAction(title: "再次提醒", isEnabled: mail.isBackendReady) { ... }) // 可选
Divider()
```

- 宽度撑满，高度跟随内容；文字可以换行，按钮 `fixedSize` 保持完整尺寸。组件本身不带 Divider，放在内容上方时在下面加一条，放在底部时在上面加一条。
- 不要给它或它外层加 `fixedSize(vertical:)`，原因见首败第 2 条。
- R8 的“已读同步未完成”可以这样用：`NoticeBar(tone: .warning, systemImage: "arrow.triangle.2.circlepath", title: "已读同步未完成。" + warning, action: InlineAction(title: "重试已读同步", isEnabled: !mail.isReading && mail.status?.state == .online) { Task { await mail.retryRead() } })`，放在邮件头部和正文之间，下面接 Divider。图标和文案由 R8 定。

```swift
SidebarHeader(status: SidebarStatus(tone: .healthy, text: "邮箱已连接",
                                    detail: "a@b.c · 同步于 22:08",   // 可选，灰字最多两行
                                    error: mail.errorMessage,         // 可选，红字最多四行
                                    action: InlineAction(title: "检查配置") { ... })) { // 可选，状态行右侧
    Text("会话")                    // 标题槽：统一 headline 字号，可以放 Menu
} actions: {
    Button("管理") { ... }          // 操作槽：统一 small 控件尺寸
}
```

- `SidebarStatusTone`：`.healthy` 绿、`.neutral` 灰、`.warning` 橙、`.error` 红；`.error` 的状态句也是红字。`isAbnormal`（橙、红）决定侧栏收起后工具栏是否露出状态。
- 只有标题没有操作时可以省略 `actions:`。
- 邮件状态由 `MailState.sidebarStatus(now:)`（`EmailWorkspace.swift`）生成，聊天状态由 `ConnectionDisplay.sidebarStatus`（`MainView.swift`）生成。R8 若要改邮件状态的文案或 error 的去留（U1-22），改 `sidebarStatus(now:)` 即可，不用动组件。
- 工作区结构：`ModuleSidebar(switcher:) { 头部 + 列表 }` 负责侧栏列宽；`CollapsedSidebarStatus(status:visibility:)` 是工具栏内容，放在工作区的 `.toolbar` 里。
