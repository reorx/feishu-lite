# G2a：自动基线与系统、键盘边界验收

## 概要

在 master 的 `e2c0f80` 上执行协调计划 G2a，协调计划标注的审阅基线为 `fb531f6`。后端 **311**、Core **74**、App **98** 项全部通过，Debug 构建成功。未知能力稳定加载、邮箱故障期间聊天 Return、真实中文输入法 markedText 路径、运行中通知权限关闭/恢复、410/旧账号/旧聊天 payload 的真实通知点击，以及注入的部分 add 失败恢复均取得证据。

**没有确认产品缺陷。R3 的 Tab/Return 保留未验**：当前系统键盘导航关闭，局部进程参数不能使系统开启完整键盘导航；未取得“再次提醒”按钮的实际 Tab 焦点，因此不能声称 Return 触发通过。所有 G2a 项均已有结论和证据；是否在此边界下签收、何时补验由协调者决定。不开始 G2b 或 G1。

只新增本报告；产品代码、共享状态文档及用户的 `kb/todo.md` 均未修改。所有工具、源码副本、日志及 **24 张截图**归档在：

`tmp/2026-10-17-email-reader-finish/g2a/`

下文证据文件名均相对此目录。`final-evidence-audit.json` 是时间关联、来源差异及结果的机器可读索引，`image-audit.json` 保存截图尺寸与非黑图检查。截图另经实际查看，不能用脚本退出码代替屏幕判定。

## 原生键盘证据

有效结果使用 CGEvent 虚拟键码的 down/up 投递，记录在 AppKit local monitor；输入经过真实 NSTextView 和生产 delegate。`chat_continue.py` 的 `a1`/`t2` 及 `ime_context.py` 的最终结果均没有调用观察工具里的 `native-key` 命令，也没有用鼠标“发送”替代 Return。

| 文本 | 原生 Return 时间（Unix 秒） | Composer `insertNewline:` | POST 时间 | native → POST |
| --- | --- | --- | --- | --- |
| a1 | 1792232451.332439 | 同 eventTimestamp 238894.659630458，focus=true、marked=false | 1792232451.337176 | 4.74ms |
| t2 | 1792232454.864012 | 同 eventTimestamp 238898.180983125，focus=true、marked=false | 1792232454.870142 | 6.13ms |
| nihao，组字结束后的第二次 Return | 1792232631.594657 | 同 eventTimestamp 239074.910850416，focus=true、marked=false | 1792232631.608086 | 13.43ms |

组字中的第一次 Return 为 `1792232630.247838`，inputSource=Rime、marked=true，随后没有聊天 POST。IME 消费该按键，结束组字后才由下一次 Return 进入生产发送 delegate。本轮总计三个聊天 POST，精确文本为 `a1`、`t2`、`nihao`，全部只到合成服务。

`audit.py` 独立核对每个 POST 只有一个对应原生 keyDown 和一个同 timestamp 的 Composer 调用，并校验 410/旧账号/旧 payload 三次真实 delegate 回调、权限切换同 PID、部分失败前无 ack / 恢复后 ack：`evidence-audit.log`。可复查原始 `events.jsonl` 与 `final-control.json`，没有用仅剩的 UI 文本倒推请求。

- 当前 mac 源码复制到 tmp 后，经副本 Makefile 构建；独立 bundle `com.reorx.FeishuLite.g2a-acceptance`、显示名“FeishuLite G2a 合成测试”。使用可用的 Apple Development 签名，仅用于隔离副本的系统通知；不改正式工程签名。
- 独立 HOME、CFFIXED_USER_HOME、FEISHU_LITE_HOME；外部合成服务只监听18881，18881–18889启动前全部可绑定。没有读取真实账号目录或 `tmp/feishu-mail.env`，没有启动真实 Python backend / 飞书 / IMAP；未复制 Local.xcconfig 或 env 文件。
- fake `MailSecItemOperations.system` 返回不存在/写删成功，未访问真实钥匙串。AppDelegate 中用测试偏好播种替代正式旧域迁移，避免读取 `com.reorx.FeishuChat` 的正式偏好；未知 receipt 只播种本次合成账号401。

- 系统键盘导航属于全局前提，局部参数无效后不改全局设置，不以强制焦点或修改 SwiftUI focus 行为获得 R3 通过。IME 只选择已启用的输入源，未增删输入法、改变快捷键或 Rime 配置，结束恢复 ABC。

## 首败和工具错误

以下原始失败均保留，未静默改记为通过，也没有据此提出产品修复。

1. 自动基线首次重定向路径错误：在 backend 工作目录误建了相对 tmp 空目录，根目录日志路径尚不存在，因此命令未运行测试。删除空目录并改绝对路径后才取得有效基线。`baseline-first-error.txt`；测试本身没有失败。
2. 复用 fixture 时错误调整了目录层级，找不到旧通知 fixture。`first-initial.log`、`first-fixture.log` 保留 FileNotFoundError；定向停止首个 caffeinate，修正后启动95555/95556这一组资源，后续未重置服务状态。
3. **观察器读取键盘 NSEvent.eventNumber 导致异常、中断分派**：早期 local monitor 无有效按键日志；直接 postEvent/sendEvent 诊断也不能构成通过证据。`keyboard.log`、`input-diagnose.log`、`keyboard-direct.log`、`app-sample-first.txt`、`Probe-v3-invalid-eventNumber.swift`、`observer-error.txt` 保留原始记录。改读 timestamp 后，真实 CG 按键、文本变化、delegate 和 POST 均可关联；最终结果只取修正后的记录。
4. 早期无间隔 down/up 的 AX helper 不够可靠，后续使用 `input` 每次 down/up 间隔70ms及 `physical-keys` 逐键输入。一次退出测试 App 后 frontmost 查询短暂出现 loginwindow；wake-screen确认就绪、screenLock为off，没有据此要求用户解锁或把它当产品问题。
5. 长文本 `g2a-auth-return` 首次键入中途失去激活，只得到 `g2a-auth-r`，等待精确草稿失败：`chat-return.log`、原生事件。之后重新激活并明确焦点，以完整短文本 `a1`/`t2`取得有效结果；未把残缺输入当草稿丢失或 Return 产品缺陷。
6. 外部 helper 选择 Rime 返回0，但实际输入上下文仍是ABC，得到未组字的 `nihao`；`ime-result.json` 保留未验结论。后续通过 App 的 NSTextInputContext 选择已有Rime，取得真正 markedText=true，才产生限定通过结论。两轮证据不混用。
7. 工具补丁曾因 cc-format 自动换行而未匹配，重新按实际文件位置应用；没有主动运行 formatter/style linter。隔离工具编译的 deprecated activate API 警告不影响产品基线。

1. **R3 Tab/Return仍未验**。本机完整键盘导航关闭，进程级 AppleKeyboardUIMode=3无法改变该系统状态。现有结果不够判断产品缺陷；需要协调者安排有可用键盘导航前提的桌面，再以原生Tab实际聚焦、原生Return及ack/投递对应记录补验。不要把这次鼠标点击其他通知、旧R3布局通过或局部参数存在当作R3键盘通过。
2. 可缩小原未验记录：未知能力稳定加载、故障期间Return、真实中文输入法markedText、运行中权限切换、410/旧账号/旧payload及注入部分add已取得本报告限定证据。汉字候选选择、真实系统add故障/掉电窄时序没有验证，不扩大结论。
3. 没有确认产品缺陷，故没有提交产品缺陷最小复现或发起返修。首败均为工具或桌面前提问题，原始日志已保留；不应为这些观察器错误开产品返修。
4. known-issues、next-up、根/mac AGENTS、README、原计划与协调记录保持只读，由协调者按上述准确边界更新。用户的todo改动未暂存。
5. G2b/WebKit竞态安全和G1真实邮箱全部未开始；本报告不替代真实邮箱、真实断网或睡眠验收。协调者可复用当前fixture/观察副本，但须移除已不需要的注入、重新创建独立HOME并按自己的端口范围启动。
