错误文案只使用固定字符串：包括发送、最新消息、更早消息、获取二维码、图片这 5 个场景。HTTP 401 提示本机访问凭证，403 提示权限，404 按会话/图片区分，408/504 提示超时，429 提示操作频繁，其他 5xx 提示服务暂不可用，其余给通用文案；未知异常、URLSession 错误也不回显系统原文。

`BackendError.http(status:detail:)` 保留诊断信息；响应 body 继续沿用原有的前 200 字节上限，没有扩大记录范围。`BackendClient.check` 用现有 os.Logger 写入 `com.reorx.FeishuLite` / `backend-http`，因此图片下载错误也能留下诊断。`http-diagnostics.log` 已实际捕获合成状态码 502 与合成 body。409 只有 `detail == "logged_out"` 才映射登出，其余仍保留普通 HTTP 错误；`Conversation` 继续等待状态事件处理登出，不覆盖既有错误，不破坏发送失败恢复草稿。

### 邮件永久错误完整清单

依据 `backend/src/feishu_lite/mail/{api,mime,html,imap,transport,store}.py` 当前实际错误码，重试同一封正文不会改变内容或读取上限：

| code | 原因 |
|---|---|
| `malformed_mime` | 邮件格式损坏 |
| `malformed_encoding` | 正文编码损坏 |
| `unsupported_charset` | 不支持的字符集 |
| `unsupported_transfer_encoding` | 不支持的传输编码 |
| `unsupported_body` | 没有受支持的可读正文 |
| `mime_too_deep` | 嵌套层级超限 |
| `too_many_parts` | 组成部分数量超限 |
| `body_too_large` | 正文大小超限 |
| `headers_too_large` | 头部大小超限 |
| `response_too_large` | 数据/响应大小超限 |

这些文案均说明原因并建议使用飞书邮箱查看，不含“重试”。`malformed_response` 仍可重试，因为它也表示通信/响应解码异常，不能推定正文永久损坏；离线、超时、队列繁忙、transport_failed 和未知错误同样保留重试。404/410 沿用现有返回收件箱的流程。

正文错误分类参与 Observation。任何 `bodyLoadState` 变化都清除旧分类；只有当前选中身份的正文请求失败才附上分类，迟到错误不能污染新选择。正文渲染失败继续视为可重试，显示证明和已读链路未变。

### 会议格式决定

只解析 `type == "video_chat"`，严格按 `_meeting_text` 的末尾两行提取会议号和入口，前面的全部内容作为主题。这能保留多行主题，并避免主题里的“会议号”被误当元数据。有效公开会议号为 9 位 ASCII 数字，保留前导零；分组文本和入口中的数字必须一致，入口必须精确为 `https://vc.feishu.cn/w/<number>`。无主题返回 nil topic；占位、缺号、无效号、链接不匹配或格式变化都返回 nil，让 R9 回退原文，不猜测会议号或链接。

## 给 R8/R9 的接口说明

### 聊天错误（R9）

Core：`BackendError.Action` 为 `.send`、`.loadMessages`、`.loadOlderMessages`、`.getQRCode`、`.loadImage`。

```swift
let text = BackendError.userMessage(for: error, action: .send)
// 已知 BackendError 也可用 error.userMessage(for: .send)
```

`Conversation.loadError`、`sendError` 和 `LoginModel.Phase.failed` 已经存放新文案，视图直接显示，别再拼 `localizedDescription`、状态码或 body。R9 只需处理错误区域样式及加载重试入口。

### 邮件正文（R8）

Core：`MailAPIError.isBodyRetryable: Bool`；Model：`MailState.canRetryBody: Bool`。

`canRetryBody` 只有当前状态为 `.failed` 且错误可重试时才为 true；idle/loading/loaded 均为 false。现有 `BodyLoadState.failed(String)` 的形状保持不变，视图无需解构新关联值，也无需读取内部 `bodyFailure`。

```swift
if case let .failed(text) = mail.bodyLoadState {
    Text(text)
    if mail.canRetryBody {
        Button("重试正文") {
            Task { await mail.selectMessage(mail.selectedMessageID) }
        }
    }
}
```

永久错误仍保留邮件头部和选择，未提交已读。不要改 `displayedBodyRoute`、render token 或可见性已读流程。

### 图片（R9）

Core：`ImageMessageFailure: Equatable, Sendable`，提供 `message: String`、`canRetry: Bool`。

```swift
// 在图片视图中保存 ImageMessageFailure?，替换当前 String? error。
// 下载 catch（保留现有 Task.isCancelled 判断）：
self.failure = ImageMessageFailure(error: error)
// NSImage 解码失败的分支：
self.failure = .decodingFailed
// 失败占位：
if let failure {
    Text(failure.message)
    if failure.canRetry {
        Button("重新加载") { attempt += 1 }
    }
}
```

404 → “图片已撤回或不可用”，不重试；`.decodingFailed` → “无法显示这张图片”，不重试；其他错误 → 按图片场景给安全文案，可重试。取消不是可展示的失败，调用方仍须先退出。不要动 R5b 的必传 `isVisible`、真实 viewport 来源以及 `.task(id: isVisible ? attempt : nil)` 的按需下载/取消链路。

### 会议邀请（R9）

Core：`MeetingInvitation: Equatable, Sendable`，通过 `message.meetingInvitation` 或 `MeetingInvitation(message:)` 取可选值。属性为 `topic: String?`、`number: String`（未分组九位号）、`formattedNumber: String`、`joinURL: URL`。

```swift
if let meeting = message.meetingInvitation {
    VStack(alignment: .leading) {
        Text(meeting.topic ?? "视频会议")
        Text(meeting.formattedNumber)
        Link("加入会议", destination: meeting.joinURL)
    }
} else {
    Text(message.text)
}
```

会议卡片是展示改动，不要修改 wire 或缓存。继续保持普通 VStack、基于 viewport 的历史分页和图片可见性。R9 修改消息行后，按 brief 跑 R5b 的 `repro2`、`minimal-sheet-resize` 各 50 轮。
