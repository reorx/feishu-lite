# R5b：会话详情卡死（U1-01）

接续 [R5 调查总结](2026-10-18-ui-r5.md)，范围和完成标准见 [协调 brief](../plans/2026-10-18-ui-fixes-coordination.md)。证据均在 `tmp/2026-10-18-ui-fixes/r5b/`，以下路径相对于该目录；未改动 R5 的证据。

## 结果

**U1-01 已修复，R5b 完成标准全部达到。** 完整复现、最小失败序列和另外四类操作各 50 轮通过，共 300 轮；测试与 Debug 构建通过。

本次只运行 `com.reorx.FeishuLite.r5b-ui`，使用合成服务、独立 HOME/数据/偏好、fake SecItem 和静默通知。没有连接真实飞书或邮箱、读取正式数据或钥匙串、启动或结束正式 App，没有 push、发布或打 tag。

## 根因与对照

**已定位到消息详情的 `LazyVStack` 与可变高度消息行的布局交互，不能再把几何回调回写当作唯一根因。** 在预览关闭后改变窗口尺寸，再滚动时，SwiftUI transaction / AttributeGraph 更新不收敛，原生文本 intrinsic size 和 fallback alignment 反复失效。改用确定布局的 `VStack` 后同样的触发步骤收敛。

这是根据宿主二分和采样确定的缺陷边界。框架内“估算尺寸与原生文本失效互相触发”的具体反馈边是推断，未声称已经定位 Apple 私有实现中的某一行。采样证明的是主线程持续计算图更新，并非网络等待或锁等待。

### 先补齐 R5 的未决实验

`r5-no-callback-exact` 重新使用 R5 留下的实际 `ConversationView`、`ScrollAnchors` 和两列表实现（位置回调置空，其他入口保持当时状态）。构建通过；`repro2` 完成 1 轮后卡死，心跳停更 7.257 秒，取样时 CPU 87.2%。`r5-no-callback-exact-repro2-failure-sample.txt` 再次捕获 `GraphHost.runTransaction`、`AG::Graph::UpdateStack::update`、`SelectionOverlay.updateNSView`、`FallbackAlignmentProvider` 与 intrinsic-size 失效。

因此 R5 最后的超时现在有了独立采样支持，确实可以在该版本上复现同源卡死。R5 的去重、原生滚动观察和文本替换都仍保留了懒加载消息容器及其尺寸协商；关闭一种应用回写或换一种文本实现，没有移除这条布局更新路径。原始 U1 两份采样中的几何上报、SelectionOverlay 是这个图循环的参与者或被反复更新的下游，不能仅凭栈热点确定唯一原因。

### 视图树二分

- `minimal-text-rows`：去掉发送者、时间分隔、文字选择和悬停提示，保留可变高度文本气泡与图片；最小序列仍在 1 轮后失败。这是继续缩减后仍能复现的宿主，见 `variants/minimal-text-rows/`。
- `image-only-rows`：只保留两个可成功预览的图片行，其他行换成固定高度空块，去掉历史标题；最小序列 **50 轮 / 97.684 秒**通过。可变高度文本行是原宿主的重要差异，图片 sheet 本身不足以触发。
- 左对齐 `LazyVStack`、给每行撑满宽度、给整行 `fixedSize`、加 `scrollTargetLayout`、把 sheet 提到滚动容器外层，都仍在第 1 轮后失败。完整失败记录及采样分别在对应 `*-stress.json`、`*-failure-sample.txt`，源码在 `variants/`。
- 只把消息容器换成普通 `VStack`，其余原行为保持，完整 `repro2` **50 轮 / 132.953 秒**通过，结束 CPU 1.4%。最终产品再加上下面的行为保护，重新运行全部压力路径。

这些结果也解释了 R5 的失败尝试：去重只能消除应用自己的无效通知；原生滚动观察只能移除几何 preference；去掉默认底部锚点、换可选择文本仍保留了可变高度行在懒栈中的测量。缺陷不依赖某一种文本选择实现，单独消除这些热点都不足以使布局收敛。

## 最终修改与行为保护

- 消息详情改用普通 `VStack`，保留文字选择、气泡、默认底部锚点和现有的滚动恢复方式；没有引入 macOS 15+ API。
- `ScrollAnchors` 仅发布纵向范围；三处使用方仅在首行/底部语义改变时写缓存或视图状态。原来的无条件回写确有问题，单独的红灯测试已证明，但它并非卡死的全部原因。
- 普通栈中所有行都会创建，不能再用历史标题的 `onAppear` 判断进入屏幕。现在用标题实际 viewport 可见性驱动分页，仍保持翻页前的首行位置；历史标题不写入消息恢复锚点。
- 同样保住图片按需加载：只对进入 viewport 的图片启动下载，已解码图片保留；离开屏幕会取消未完成加载。没有修改预览尺寸、气泡样式、错误分类等 R9 内容。
