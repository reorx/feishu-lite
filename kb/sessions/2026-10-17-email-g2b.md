# G2b：WebKit 竞态与安全边界验收

## 概要

**G2b 四项均取得限定范围内的通过证据，没有确认产品缺陷。** 真实 WKNavigation 的旧 didFinish、HTML 恢复导航及原生 TextKit 旧 layout 回放均不能提供错误显示证明或触发 read；read 响应暂停期间更换合成账号或 UIDVALIDITY，旧响应没有污染新身份的选择、未读行、整箱计数和 Dock badge；HTTPS 普通及 `_blank` 点击真实外开并加载本机 TLS 页面，单标签内网 URL 保留并交给默认 Chrome；恶意正文首载与恢复均无法取得另一封邮件、聊天、接口 token 或合成 token 文件。

开始HEAD为 `56d0686`（包含用户指出的协调提交 `13e89c9`）；提交前HEAD为并行G1阶段一签收的 `5d1ed2b`。两者之间只有G1报告和协调文档，mac/backend产品文件无变化。沿用已签收 `9119dfb` G2a 的后端311 / Core74 / App98与 Debug 构建基线，不重复旧矩阵。本轮隔离副本两次 `make build` 成功，只改 tmp 中的 fixture、观察及回调调度工具，未改产品代码、测试源文件或共享状态文档。

证据及 **30 张截图**全部在：

`tmp/2026-10-17-email-reader-finish/g2b/`

下文文件名均相对此目录。`evidence-audit.json` / `.log` 是导航、显示、read、精确攻击目标及源文件哈希的交叉核对；`image-audit.json` 确认30张截图非黑图。已实际查看关键正文、拒绝旧回调、身份清空、计数及外部浏览器截图，结论不只来自脚本退出码。

## 关键时间与归因

`events.jsonl`记录每一个实际WK didFinish、navigation对象身份、预期navigation、render token、stopped和候选/接受结果。旧句柄投给当前controller时，stopped=false但navigation不匹配；旧接收者自己的句柄相符，但stopped=true。两种拒绝都在初次read之前观测，不能用“已经读过/请求去重”解释。恢复流程另有真实didStart和新navigation，不用人工构造WKNavigation。

整轮共8次read-submit和8次服务端read请求，每次提交前均有同token的body-display-accepted。6次当前结果返回Swift并成功处理；另2次是在途换身份的旧请求。App的生产身份失效逻辑取消read任务；服务仍在释放后生成旧成功payload，但客户端没有新的read-result接受记录，新身份界面和计数保持不变。**本轮验证了实际取消路径及结果隔离，没有绕过URLSession取消来强迫旧成功值进入Swift，也不宣称独立覆盖了该假设路径中的每一个guard。** 对应旧/新scope与时间在`identity-results.json`和`requests.jsonl`，不是实际IMAP STORE或邮箱flags写入证据。

攻击页直接返回未净化HTML，生产CSP、禁JS、非持久存储、block-all、精确主文档规则与两delegate保持不变。首载和恢复各有一个主文档scheme请求，没有别的scheme请求，HTTP攻击计数为0；另用无token正向控制确认服务确实会记录并401拒绝。公开WK find用于搜索，不调用evaluateJavaScript来执行攻击，避免工具自身突破禁JS设置。find可能滚动到匹配位置，本轮截图不承担重新验证滚动恢复落点的结论。

HTTPS真实Chrome页面有主文档GET和屏幕文字，未把router回调或打开URL日志单独当作页面加载成功。单标签内网只签收外开，主机实际内容未验。初次证书隐私页属于自签TLS环境，不是邮件renderer失败；没有将其隐藏成首次就直接成功。

## 隔离、源码差异与自己的决定

- 完整读取协调计划及其必读：根/mac AGENTS、续接第二/三节、原计划界面/规则/验收、桌面测试文档、F1b全文、R1和D2正文显示/已读契约。使用kb整理报告、systools清理；尝试agent-browser附着默认Chrome后，因无调试端口改用精确测试URL的原生AX/AppleScript核对。不委派、不新建tab、分支或worktree。
- GUI前`agent-inspect-session.sh`为23%；中途26/28/31%，收尾仍低于40%。每次截图先wake-screen，有限caffeinate保护屏幕，没有更改系统外观、输入法、键盘导航或其他全局设置。
- 从当前mac源码新复制到tmp，独立bundle `com.reorx.FeishuLite.g2b-acceptance`，显示名“FeishuLite G2b 合成验收”，副本Makefile构建、ad-hoc签名。独立HOME/CFFIXED_USER_HOME/FEISHU_LITE_HOME，启动直连18891的合成服务；TLS只监听18892。启动前18891–18899全部可绑定，不使用G1的18911–18919。
- 没有复制Local.xcconfig或env，没有读取`tmp/feishu-mail.env`、正式数据目录、真实邮箱/飞书或真实Keychain。AppDelegate用自己的模块偏好播种替代正式旧域迁移；MailSecItemOperations全部fake，读取notFound、写删成功。没有G2a的能力延迟、通知播种或add错误注入。
- 副本仅6个生产Swift文件不同：AppDelegate接观察器/独立偏好；MailKeychain接fake；HTMLController记录生命周期、策略和navigation，并把真实didFinish交给可控调度器，原guard完整保留；PlainController同样调度原生layout，原guard完整保留；HTMLDocument记录scheme请求；MailState+Reader只加显示/read时间观察。另增G2bProbe。`source-differences.patch`与最终哈希在`evidence-audit.json`，源仓库对应文件哈希均未变。
- 延迟回调保留真实controller/句柄，在原生产判断函数入口回放；观察器临时强引用已stop对象，便于确定性重放，未更改缓存所有权、安全规则、已读条件或停止逻辑。**这是受控回调调度，不宣称WebKit在未经注入的自然时序下实际产生了同一乱序。**
- 为确保跨邮件测试指向精确有效目标，第二次安全运行把目标选择从任意旧URL收窄为最近展示的另一封157，并记录账号/validity/URL，另保存最终包装文档。第一次通过证据保留为`security-first-results.json`和`first-19/20/21-*`；最终结论以明确目标的第二次为准。修订只涉及观察/合成样本替换，不放开正文策略。
- 默认Chrome没有CDP；不重启或改用户浏览器配置。第一次确认外开后，用新建的本次专用Chrome窗口继续TLS/内网验收，结束只关闭精确测试URL和该自建空窗口。没有从App把token传给浏览器。自签证书例外只经浏览器本次页面允许，未导入系统钥匙串或修改系统信任；已停止服务并删除临时TLS私钥。

## 首败与工具错误

1. `agent-browser --session mailfin-g2b-links --auto-connect tab list --json`失败：默认Chrome未开放调试端口。原始`browser-connect-first.json` / `.log`保留，没有创建可用浏览器会话，没有把工具不可连接当产品失败。之后只对精确合成URL用原生工具取证，不设置Chrome调试参数或全局JavaScript from Apple Events。
2. `links_finish.py`末尾最初对所有TLS请求都要求Referer为空，因Chrome自行请求favicon、带正常同源Referer而失败。源脚本和输出保留为`links_finish-first-favicon-assumption.py` / `links-finish-first-favicon-assumption.log`。已完成的点击和页面证据不重跑；`links_audit.py`明确区分两次用户主文档和浏览器后续favicon，主文档均无Referer/Authorization，全部请求都无Authorization。不是token泄漏或产品回归。
3. `audit.py`首次漏导入Counter，NameError发生在审计脚本中，未完成审计；`audit-first-nameerror.py` / `evidence-audit-first-nameerror.log`保留。补齐导入后完整交叉核对通过，最终输出是`evidence-audit.log`。
4. 首次browser cleanup关闭最后一个测试tab时，Chrome自动关闭自建窗口，随后工具继续取已消失窗口id，报-1728并中止后续清理。`browser_cleanup-first-closed-window.applescript`及`cleanup-first-closed-window.log`保留；改为存在性检查后重跑完整清理，最终`resource-cleanup.json`与`final-resource-check.json`证明清干净。未把第一次退出码解释为清理成功。
5. 启动脚本尚未完成时，首次读取`01-inbox-ax.txt`得到文件不存在；等待启动脚本结束后才取得有效01证据，没有把提前轮询当App未启动。此输出保留在本tab工具记录，采证脚本自身正常退出。

没有主动跑formatter/style linter。脚本运行都先写到本次tmp目录，再用uv执行；没有复杂Python/Node inline。构建日志为`build-first.log`和`build-final.log`，均Build Succeeded。

- 用release-retained清空观察器临时保留的controller、navigation和layout，再正常退出本测试bundle；未调用全局pkill/make run，不结束正式App。
- 只停止`resource-pids.json`中的fixture/TLS服务进程组和caffeinate。18891–18899全部重新可绑定，lsof无监听；`final-resource-check.json`确认原PID无本次进程残留。G1端口未操作，桌面已释放。
- 本测试bundle偏好域及精确plist已删除，`defaults read`确认域不存在；独立home/data已移除，合成token文件随之删除。没有真实SecItem条目、通知或钥匙串授权需要清理；本轮没有投递系统通知、弹扫码页或钥匙串授权框。
- 精确测试HTTPS和intranet标签全部关闭，最后检查无匹配URL；自建Chrome窗口已关闭，保留用户原有浏览器。没有修改系统证书信任，临时TLS私钥已删除；公钥证书、源码副本、合成文档、日志和截图留作证据。测试App路径已从LaunchServices注销。
- 未启动模拟器。`mac-dev-cleanup --only browser --min-age 2`的dry-run和实际均nothing to clean，见`browser-cleanup*.log`；没有清理其他会话资源。
- 清理主证据：`resource-cleanup.json`、`cleanup.log`、`final-resource-check.json`。无需协调者继续处理活的验收资源。

## 未验证项与交给协调者

1. 可按本报告准确边界收窄原F1b/F1c遗留：旧HTML/恢复navigation及纯文本layout、在途read换账号/UIDVALIDITY、HTTPS与单标签内网外开、跨邮件/token/聊天动态攻击都取得本轮证据。四项没有确认缺陷；无需因工具错误开返修。
