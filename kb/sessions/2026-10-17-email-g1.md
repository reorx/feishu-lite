## 执行与证据

只通过 `uv run --project backend feishu-lite-backend --port 18911` 运行真实源码后端，分别使用 G1 目录下的 `isolated-home/` 和 `older-supplement/isolated-home/` 作为独立 FEISHU_LITE_HOME。端口先确认可用；所有账号配置、试连和凭证注入只经鉴权 API，未修改生产配置或缓存。

实际命令（均不含凭证值）：

```sh
uv run --project backend python tmp/2026-10-17-email-reader-finish/g1/scan.py
uv run --project backend python tmp/2026-10-17-email-reader-finish/g1/summarize.py
uv run --project backend python tmp/2026-10-17-email-reader-finish/g1/older_scan.py
uv run --project backend python tmp/2026-10-17-email-reader-finish/g1/finalize.py
```

- `scan.py`、`older_scan.py`：验收工具，仅在 tmp，不修改产品。
- `result.json`、`overview.json`：首轮聚合统计、每次正文 HTTP 状态/耗时/长度；没有主题、发件人、收件地址或正文。
- `older-supplement/result.json`：追加较早正文的选中 MIME 叶子结构与计时，仅保留媒体类型、section、charset、transfer encoding、编码后大小；没有原文。
- `scan-progress.log`、`older-progress.log`：脱敏进度；`backend.log`、`older-supplement/backend.log`：后端生命周期原始日志。
- `final-audit.json`、`manifest.json`：结束时的断言、凭证审计、资源检查和证据 SHA-256。

## 自己做的决定、首败与工具修正

- 使用达到一年以前即可停止的计划许可，在第 4 页停止；不将加载的 250 封当作整箱邮件总数。
- 首轮采样脚本从历史页页首补足 150，不能保证恰好覆盖该页一年以前的正文。审查发现这个覆盖不足后，保留首轮原始结果，另建独立目录补取全部 10 封较早正文；没有把初次覆盖不足隐去或改成已通过。
- 没有 API 失败、正文解析失败或需要原文复现的目标，因此没有保存 UID 失败清单或脱敏原文。
- 最终审计脚本清理冗余语句时，一次 patch 因 post-edit 钩子已将双引号改为单引号而匹配失败；读取实际文件后修正。原始错误保存在 `tool-errors.log`，未将工具错误记作产品失败或静默丢弃。
- uv 进程组主动收到 SIGTERM 后退出码为 143；四次后端运行日志均有 application shutdown complete 与 finished server process，属于本次定向关停，不作后端崩溃记录。
- 无产品改动，不重跑 G2a 已签收的全量自动基线，不启动桌面验收工具。
